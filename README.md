# 🎭 剧场排练走位工具（Stage Blocking Tool）

一个面向剧场排练的轻量 Web 工具：在 **8 × 6 舞台网格**上设置演员起点，**逐拍**指定每位演员的「上 / 下 / 左 / 右 / 原地」动作，自动推演全部演员位置，并标出走位冲突；可基于当前推演一键生成**只读的「排练场记报告」**快照，并能在两份快照之间做**报告对比**（逐拍坐标/动作差异与冲突变化）。

- 零第三方运行时依赖：后端只用 Node.js 内置模块，前端不用任何框架 / CDN / 账号
- 走位表与场记报告均自动保存在**浏览器本地**（localStorage），刷新或重启后可继续使用
- 一键 Docker 启动，默认访问 <http://localhost:3000>

---

## 一条命令启动（推荐：Docker）

```bash
docker compose up --build
```

然后浏览器打开：

> **http://localhost:3000**

后台运行加 `-d`：`docker compose up -d --build`；停止：`docker compose down`。

查看后台日志：`docker compose logs -f`；改完代码重新构建：`docker compose up -d --build`。

> 容器只提供静态页面与 `/health` 健康检查，**不挂载任何卷、不写数据盘**：走位与报告都存在访问者浏览器的 localStorage 中，因此销毁 / 重建容器（`docker compose down && docker compose up --build`）不会影响存档；但更换浏览器、无痕模式或清除站点数据会使存档不可见，请用「导出 JSON / 下载报告 JSON」做跨机归档。

也可不使用 compose，直接构建镜像：

```bash
docker build -t stage-blocking-tool .
docker run --rm -p 3000:3000 --name stage-blocking stage-blocking-tool
# 自定义端口：-e PORT=8080 并把映射改为 -p 8080:8080
```

首次打开会自动载入一段示例走位（包含互换、碰撞、越界拦截三种情况），便于直接体验；清空后即为空白工程。

## 不用 Docker：本机 Node.js 直接运行

需要 Node.js ≥ 18（内置 node:http / node:fs，**无需 `npm install`**）：

```bash
npm start        # 等价于 node server.js
# 或
node server.js
```

打开 <http://localhost:3000> 即可。

## 使用说明

### 舞台坐标

- 网格 **8 列 × 6 行**，坐标显示为 `列-行`（如 `4-2` 表示第 4 列第 2 行）
- **第 1 行靠近观众席**（舞台下方），**第 6 行靠近上场方向**（舞台上方）
- 动作方向：**上 △**（行号 +1，远离观众）、**下 ▽**（行号 −1）、**左 ◁**（列号 −1）、**右 ▷**（列号 +1）、**原地 ·**

### 基本流程

1. 点击右侧「**＋ 添加演员**」，自动进入起点设置模式
2. 在舞台网格上点击一个格子，作为该演员的**起点**（再点同一格取消，按 `Esc` 或点行内 `◎` 退出模式）
3. 在底部「走位表」里，为每位演员的每一拍选择动作；也可以点「＋ 添加拍」增加拍数
4. 用顶部 **◀ ▶ / 进度条 / 播放按钮** 逐拍查看推演结果；键盘 `←` `→` 也可切拍
5. 需要对比两次排练（或改走位前后）的差异时：先分别「生成报告」得到两份只读快照，再用「**⇄ 报告对比**」按共同演员与拍次对齐查看差异（详见下文）

### 越界拦截

- 若某拍的动作会让演员走出 8×6 网格，该动作**立即被拦截**：下拉框回退、弹出提示（说明演员、拍、方向、所在格），该演员该拍**原地不动**
- 已保存的动作若因起点修改等原因变为越界，会在走位表中以**红框**标出，舞台对应格显示 ⛔ 角标，并出现在冲突列表中；改回合法动作后自动消失

### 冲突检测

| 类型 | 含义 | 舞台表现 |
| --- | --- | --- |
| 🔴 同拍同格 | 同一拍两位及以上演员位于同一格（第 0 拍起点重叠也会检测） | 红框高亮该格 |
| 🔁 相邻两拍互换 | 相邻两拍之间 A 与 B 正好交换格子（X→Y 且 Y→X），此类**不计为碰撞** | 两格橙色框 + 双向虚线箭头 |
| ⛔ 越界拦截 | 动作超出舞台边界被拦截 | 红框动作格 + ⛔ 角标 |

- 点击右侧冲突列表中的任意一条，会**自动跳到对应拍**，舞台上蓝色脉冲框标出对应格子，并在走位表中闪烁对应动作格
- 「定位下一个」按钮按拍顺序循环定位冲突；冲突数显示在标题红色徽标中

### 排练场记报告（只读快照）

右侧「**📝 场记报告**」面板可把某一段排练推演固化成报告：

1. 点「**＋ 生成报告**」，填写报告名称
2. 选择**拍次范围**（起点至任意一拍，起止选反会自动交换）与**演员**（可全选 / 清空，支持勾选子集）
3. 生成后打开只读报告视图，内容包括：
   - **逐拍走位记录**：每个拍次下每位演员的**坐标**与**动作**，并以 🔴 同格 / 🔁 互换 / ⛔ 越界标记状态；无起点演员显示「未参与推演」
   - **冲突汇总**：所选范围内的同格、互换、越界条目（含当事人、格子坐标、拍次），顶部给出分类计数
4. 冲突条目右侧「**↗ 跳回此拍**」可关闭报告并在走位编辑器中跳到对应拍次定位该冲突（只切换视图，**不会**用报告覆盖当前正在编辑的走位；若冲突已被修改掉，会停在该拍并提示）
5. 报告视图工具栏提供「**🖨 打印**」（纸张化打印样式，只打印报告正文，可用浏览器「另存为 PDF」）与「**⬇ 下载 JSON**」（导出该报告快照文件，文件名带时间戳）
6. 报告列表中每条可随时重新查看、单独下载 JSON 或删除

> **快照语义**：报告在生成的那一刻深拷贝所需的全部数据（演员名、起点、逐拍动作与坐标、冲突、内嵌一份当时的走位）。**生成之后再编辑走位、增删演员或拍次，都不会改变任何已生成的报告**；演员改名也不影响旧报告中的姓名。
>
> 冲突只要涉及任一被选演员即会记录，并保留全部当事人姓名（即便对方不在本次勾选范围内），便于场记核对「他和谁撞上了」；行内状态标记只标在被选演员身上。

### 报告对比（两份只读快照之间）

在「📝 场记报告」面板点「**⇄ 报告对比**」（至少两份已保存报告后可用），选择 **A 基准**与 **B 对照**两份快照（可点 ⇄ 交换两侧）：

1. 弹窗会**实时预览对齐口径**：共同演员、共同拍次（两边范围的交集）、以及冲突变化/逐拍差异的数量；仅属于一侧的演员或拍次会明确列出
2. 确认后生成只读的对比视图，并保存在下方「报告对比」列表中（随本地存档保留，可随时重新查看、下载 JSON 或删除）
3. **逐拍走位差异**：按共同演员与共同拍次逐拍对齐，每位演员一行显示 A 坐标 → B 坐标、A 动作 → B 动作；坐标或动作发生变化的格子高亮；每拍右上角「**↗ 在编辑器中打开此拍**」可关闭对比并跳回走位编辑器对应拍次
4. **冲突变化汇总**：分别按 🔴 同格 / 🔁 互换 / ⛔ 越界三类汇总——
   - **＋ 新增**：仅 B（对照）存在的冲突
   - **－ 消除**：仅 A（基准）存在的冲突
   - **＝ 保持**：两份报告中均存在的冲突

   每条可「**↗ 跳回此拍**」：在当前走位中尝试用快照里的定位键找到同一冲突；若当前走位已把它改掉，则只停在该拍并明确说明，不会假装定位成功
5. 对比视图工具栏提供「**🖨 打印**」（纸张化打印 / 另存 PDF，只打印对比正文）与「**⬇ 下载 JSON**」（导出该对比的完整快照）

> **对齐口径**：共同演员按**演员 id**匹配（同 id 改名仍视为同一人，视图显示「旧名 → 新名」；仅同名但 id 不同不算共同演员）；共同拍次取两份报告拍次范围的交集。仅属于一侧的演员、拍次，以及只涉及这些演员/拍次的冲突，都会在视图顶部的提示区明确列出，**不计入**差异与变化统计。
>
> **不重叠不误导**：当两份报告**没有任何共同演员**，或**拍次范围完全不相交**时，只保存并展示一条显著的提示性对比（说明 A/B 两侧各自的范围与演员），**不会生成逐拍差异或冲突变化数字**，避免产生看似成立、实则错位对齐的结果。
>
> **同样是只读快照**：对比在生成时固化所需全部数据（含两侧报告标题与生成时间）。之后编辑走位、改名或删除源报告，都不会改变已保存的对比；源报告被删除时列表会标注「（源报告已删除）」，对比仍可查看。

### 数据保存与迁移

- 所有演员、起点、逐拍动作、当前查看的拍号，以及**已生成的全部场记报告与报告对比**，都会在每次修改后自动写入**该浏览器**的 localStorage（键名 `stage-blocking:v1`，报告在同一键下的 `reports` 字段、对比在 `comparisons` 字段中）
- **向后兼容**：升级前没有报告/对比的旧存档可直接读取（`reports` / `comparisons` 缺失时按空列表处理）；报告与对比在加载时都会逐条校验，损坏的条目会被安全丢弃而不影响走位数据
- 刷新页面、重启容器都不会丢失；换浏览器 / 电脑不会同步（设计上完全本地、无后端数据库、无需任何账号）
- 「**导出 JSON**」导出的是走位编辑数据（用于继续编辑）；场记报告的「**下载 JSON**」导出的是只读报告快照，报告对比的「**下载 JSON**」导出的是只读对比快照（内嵌两侧报告标题、对齐口径、逐拍差异与冲突变化），三者互不影响
- 「导入 JSON」只替换走位表，**不会删除**已有报告与对比；「清空全部」会同时清空走位、本浏览器中的全部报告与全部对比
- 删除某份报告不影响已生成的对比：对比内嵌了完整差异结果，并会在源报告缺失时标注，仍可查看 / 打印 / 下载

## 项目结构

```
.
├── server.js            # Node 内置 http 静态服务器（含安全头、路径穿越防护、/health）
├── package.json         # 元信息与启动脚本（无第三方依赖）
├── public/
│   ├── index.html       # 页面结构（舞台、走位表、报告弹窗、只读报告与报告对比视图）
│   ├── styles.css       # 剧场深色主题样式（含报告/对比纸张与打印样式）
│   └── app.js           # 全部业务逻辑：推演 / 冲突检测 / 报告快照 / 报告对比 / 渲染 / 本地存储
├── test/
│   ├── smoke.mjs        # 零依赖纯函数冒烟测试（移动、越界、碰撞、互换、数据规整、报告、报告对比）
│   └── dom-smoke.cjs    # 零依赖 DOM 垫片冒烟（UI 初始化、报告/对比生成、预览、跳转、打印、下载、删除）
├── Dockerfile           # 基于 node:20-alpine 的生产镜像
├── docker-compose.yml   # 单服务编排，映射 3000 端口，含健康检查
└── README.md
```

核心推演函数 `simulate(actors, beats)` 是纯函数（位于 `public/app.js`），输入演员与拍数，输出每拍位置、越界、碰撞、互换四类结果；报告生成 `buildReport(...)`、存档规整 `normalizeReport(...)`，以及报告对比 `analyzeReports(...)` / `buildComparison(...)` / `normalizeComparison(...)` 同为纯函数。它们在 Node 环境下可直接 `require` 用于测试。

## 技术说明 / 隐私

- 后端仅提供原生 HTML / CSS / JS 静态文件与 `/health` 健康检查，不收集、不上传任何数据
- 响应头设置 CSP（只允许同源资源）、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`
- 静态文件路径做了规范化与穿越校验
- 无需任何第三方账号、API Key 或外部服务
