# 🎭 剧场排练走位工具（Stage Blocking Tool）

一个面向剧场排练的轻量 Web 工具：在 **8 × 6 舞台网格**上设置演员起点，**逐拍**指定每位演员的「上 / 下 / 左 / 右 / 原地」动作，自动推演全部演员位置，并标出走位冲突；可基于当前推演一键生成**只读的「排练场记报告」**快照，还能把**两份报告快照逐拍对比**（坐标 / 动作差异与冲突的新增、消除、保持）。

- 零第三方运行时依赖：后端只用 Node.js 内置模块，前端不用任何框架 / CDN / 账号
- 走位表与场记报告均自动保存在**浏览器本地**（localStorage），刷新或重启后可继续使用
- 一键 Docker 启动，默认访问 <http://localhost:3000>

---

## 一条命令启动（推荐：Docker）

```bash
docker compose up --build
```

然后浏览器打开：

> **http://localhost:3000**

后台运行加 `-d`：`docker compose up -d --build`；停止：`docker compose down`。

查看后台日志：`docker compose logs -f`；改完代码重新构建：`docker compose up -d --build`。

> 容器只提供静态页面与 `/health` 健康检查，**不挂载任何卷、不写数据盘**：走位、报告与报告对比都存在访问者浏览器的 localStorage 中，因此销毁 / 重建容器（`docker compose down && docker compose up --build`）不会影响存档；但更换浏览器、无痕模式或清除站点数据会使存档不可见，请用「导出 JSON / 下载报告 JSON / 下载对比 JSON」做跨机归档。

也可不使用 compose，直接构建镜像：

```bash
docker build -t stage-blocking-tool .
docker run --rm -p 3000:3000 --name stage-blocking stage-blocking-tool
# 自定义端口：-e PORT=8080 并把映射改为 -p 8080:8080
```

首次打开会自动载入一段示例走位（包含互换、碰撞、越界拦截三种情况），便于直接体验；清空后即为空白工程。

## 不用 Docker：本机 Node.js 直接运行

需要 Node.js ≥ 18（内置 node:http / node:fs，**无需 `npm install`**）：

```bash
npm start        # 等价于 node server.js
# 或
node server.js
```

打开 <http://localhost:3000> 即可。

## 使用说明

### 舞台坐标

- 网格 **8 列 × 6 行**，坐标显示为 `列-行`（如 `4-2` 表示第 4 列第 2 行）
- **第 1 行靠近观众席**（舞台下方），**第 6 行靠近上场方向**（舞台上方）
- 动作方向：**上 △**（行号 +1，远离观众）、**下 ▽**（行号 −1）、**左 ◁**（列号 −1）、**右 ▷**（列号 +1）、**原地 ·**

### 基本流程

1. 点击右侧「**＋ 添加演员**」，自动进入起点设置模式
2. 在舞台网格上点击一个格子，作为该演员的**起点**（再点同一格取消，按 `Esc` 或点行内 `◎` 退出模式）
3. 在底部「走位表」里，为每位演员的每一拍选择动作；也可以点「＋ 添加拍」增加拍数
4. 用顶部 **◀ ▶ / 进度条 / 播放按钮** 逐拍查看推演结果；键盘 `←` `→` 也可切拍

### 越界拦截

- 若某拍的动作会让演员走出 8×6 网格，该动作**立即被拦截**：下拉框回退、弹出提示（说明演员、拍、方向、所在格），该演员该拍**原地不动**
- 已保存的动作若因起点修改等原因变为越界，会在走位表中以**红框**标出，舞台对应格显示 ⛔ 角标，并出现在冲突列表中；改回合法动作后自动消失

### 冲突检测

| 类型 | 含义 | 舞台表现 |
| --- | --- | --- |
| 🔴 同拍同格 | 同一拍两位及以上演员位于同一格（第 0 拍起点重叠也会检测） | 红框高亮该格 |
| 🔁 相邻两拍互换 | 相邻两拍之间 A 与 B 正好交换格子（X→Y 且 Y→X），此类**不计为碰撞** | 两格橙色框 + 双向虚线箭头 |
| ⛔ 越界拦截 | 动作超出舞台边界被拦截 | 红框动作格 + ⛔ 角标 |

- 点击右侧冲突列表中的任意一条，会**自动跳到对应拍**，舞台上蓝色脉冲框标出对应格子，并在走位表中闪烁对应动作格
- 「定位下一个」按钮按拍顺序循环定位冲突；冲突数显示在标题红色徽标中

### 排练场记报告（只读快照）

右侧「**📝 场记报告**」面板可把某一段排练推演固化成报告：

1. 点「**＋ 生成报告**」，填写报告名称
2. 选择**拍次范围**（起点至任意一拍，起止选反会自动交换）与**演员**（可全选 / 清空，支持勾选子集）
3. 生成后打开只读报告视图，内容包括：
   - **逐拍走位记录**：每个拍次下每位演员的**坐标**与**动作**，并以 🔴 同格 / 🔁 互换 / ⛔ 越界标记状态；无起点演员显示「未参与推演」
   - **冲突汇总**：所选范围内的同格、互换、越界条目（含当事人、格子坐标、拍次），顶部给出分类计数
4. 冲突条目右侧「**↗ 跳回此拍**」可关闭报告并在走位编辑器中跳到对应拍次定位该冲突（只切换视图，**不会**用报告覆盖当前正在编辑的走位；若冲突已被修改掉，会停在该拍并提示）
5. 报告视图工具栏提供「**🖨 打印**」（纸张化打印样式，只打印报告正文，可用浏览器「另存为 PDF」）与「**⬇ 下载 JSON**」（导出该报告快照文件，文件名带时间戳）
6. 报告列表中每条可随时重新查看、单独下载 JSON 或删除（每行的「⚖」按钮可以该报告为 A 侧直接发起对比）

> **快照语义**：报告在生成的那一刻深拷贝所需的全部数据（演员名、起点、逐拍动作与坐标、冲突、内嵌一份当时的走位）。**生成之后再编辑走位、增删演员或拍次，都不会改变任何已生成的报告**；演员改名也不影响旧报告中的姓名。
>
> 冲突只要涉及任一被选演员即会记录，并保留全部当事人姓名（即便对方不在本次勾选范围内），便于场记核对「他和谁撞上了」；行内状态标记只标在被选演员身上。

### 报告对比（两份只读快照）

右侧「**⚖ 报告对比**」按钮（或报告行上的「⚖」快捷按钮）可选择**两份已保存报告**进行对比：

1. 在弹窗中选择 **A 侧（基准）** 与 **B 侧（对比）** 报告（不能是同一份）；选择后实时预览对齐范围
2. 对比按**共同演员（演员 id 相同）**与**共同拍次（拍次编号交集）**对齐：
   - **逐拍走位差异**：每个共同拍次下每位共同演员的 A / B 两侧**坐标**与**动作**并列展示，坐标或动作不同的格子高亮并标「≠」；动作被越界拦截导致「坐标相同、动作不同」同样计为差异
   - **冲突变化汇总**：在共同范围内把冲突按身份归并——同格按「拍次 + 格子」、互换按「拍次 + 两名共同演员」、越界按「拍次 + 演员」——并分别汇总 **🟢 新增**（A→B 新出现）、**🔴 消除**（B 相对 A 不再出现）、**⚪ 保持**（两侧都存在），各自再分 🔴 同格 / 🔁 互换 / ⛔ 越界 计数
3. **不重叠时明确提示且不生成误导结果**：两份报告没有任何共同演员，或拍次范围完全不相交时，弹出说明页列出各自独有的演员 / 拍次，**不生成差异条目、不打印、不导出、不写存档**；仅一方独有的演员或拍次即使可比也只在页首提示，绝不混入差异统计
4. 逐拍差异行与冲突变化条目右侧的「**↗ 跳回此拍**」可关闭对比视图并在走位编辑器中跳到对应拍次（只切换视图，**不会**修改走位或任何快照；当前走位拍数不足时会提示）
5. 对比视图工具栏提供「**仅看差异**」（逐拍表折叠完全一致的行/拍）、「**🖨 打印**」（只打印对比纸张，可另存为 PDF）与「**⬇ 下载 JSON**」（导出该次对比结果，文件名带时间戳）
6. 成功生成的对比会出现在右侧「**⚖ 报告对比**」列表中，**随本地存档保留**，可随时重新查看、单独下载 JSON 或删除；删除对比不会删除两侧原报告，删除其中一份原报告也不会删除对比（查看时会标注「原报告已从本地存档删除」）

> 对比同样是**只读快照**：结果在生成时固化（两侧报告标题、共同演员姓名、逐拍坐标 / 动作、冲突变化与计数），之后删除或重新生成同名报告都不会改变已保存的对比。
>
> 对齐依赖**演员 id**：导入 / 清空后重建的演员即使同名也视为不同演员（不会错误对齐）。共同演员在两份报告中姓名不同时，差异表以「A 侧姓名 → B 侧姓名」标注。

### 数据保存与迁移

- 所有演员、起点、逐拍动作、当前查看的拍号，以及**已生成的全部场记报告与报告对比记录**，都会在每次修改后自动写入**该浏览器**的 localStorage（键名 `stage-blocking:v1`，报告在同一键下的 `reports` 字段、对比在 `comparisons` 字段中）
- **向后兼容**：升级前没有报告 / 对比的旧存档可直接读取（字段缺失时按空列表处理）；报告与对比在加载时都会逐条校验，损坏的条目会被安全丢弃而不影响走位数据；无法对齐的对比结果从不写存档
- 刷新页面、重启容器都不会丢失；换浏览器 / 电脑不会同步（设计上完全本地、无后端数据库、无需任何账号）
- 「**导出 JSON**」导出的是走位编辑数据（用于继续编辑）；场记报告的「**下载 JSON**」导出的是只读报告快照；报告对比的「**下载 JSON**」导出的是对比结果（含共同演员、逐拍差异、冲突变化与计数），三者互不影响
- 「导入 JSON」只替换走位表，**不会删除**已有报告或对比记录；「清空全部」会同时清空走位、全部报告与本浏览器中的全部对比记录

## 项目结构

```
.
├── server.js            # Node 内置 http 静态服务器（含安全头、路径穿越防护、/health）
├── package.json         # 元信息与启动脚本（无第三方依赖）
├── public/
│   ├── index.html       # 页面结构（舞台、走位表、报告弹窗 / 只读报告视图、报告对比弹窗与对比视图）
│   ├── styles.css       # 剧场深色主题样式（含报告与对比纸张、打印样式）
│   └── app.js           # 全部业务逻辑：推演 / 冲突检测 / 报告快照 / 报告对比 / 渲染 / 本地存储
├── test/
│   └── smoke.mjs        # 零依赖冒烟测试（移动、越界、碰撞、互换、数据规整、场记报告、报告对比）
├── Dockerfile           # 基于 node:20-alpine 的生产镜像
├── docker-compose.yml   # 单服务编排，映射 3000 端口，含健康检查
└── README.md
```

核心推演函数 `simulate(actors, beats)` 是纯函数（位于 `public/app.js`），输入演员与拍数，输出每拍位置、越界、碰撞、互换四类结果；报告生成 `buildReport(...)`、存档规整 `normalizeReport(...)`，以及报告对比 `buildComparison(...)`（共同演员 / 拍次对齐、逐拍差异、冲突新增 / 消除 / 保持）与对比存档规整 `normalizeComparison(...)` 同为纯函数。它们在 Node 环境下可直接 `require` 用于测试。

## 技术说明 / 隐私

- 后端仅提供原生 HTML / CSS / JS 静态文件与 `/health` 健康检查，不收集、不上传任何数据
- 响应头设置 CSP（只允许同源资源）、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`
- 静态文件路径做了规范化与穿越校验
- 无需任何第三方账号、API Key 或外部服务
